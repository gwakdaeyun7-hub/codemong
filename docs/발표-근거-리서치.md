# CodeMong 발표 근거 리서치

> 교수님 피드백("왜 이렇게 설계했는지 근거·신뢰성을 보여달라") 대응용. 팀장 정리 4개 항목(① 스파이더 5축 근거, ② 진단 신뢰성/루브릭, ③ AI 모델·비용, ④ 수익모델)에 대해 실제 인용 가능한 논문·플랫폼·가격 근거를 조사·정리했다. **모든 URL은 실제 접속 확인함.** (조사일 기준 2026년)

---

## 요약 (발표 슬라이드 3줄)

1. **5축은 임의가 아니다** — 자동 코드평가 연구(Ala-Mutka 2005) + 컴퓨팅 사고력(Wing 2006, Brennan-Resnick 2012) + 기존 플랫폼(solved.ac, LeetCode, HackerRank, CodeSignal)의 평가 방식을 참고해 초보 학습자 진단 목적에 맞게 5축으로 재구성.
2. **신뢰성** — AI가 임의 평가하는 게 아니라, 우리가 먼저 루브릭을 정의하고 AI가 그 기준대로 분석 + **감점 근거를 함께 반환**. 2026년 LLM-as-a-judge 연구의 공통 권고와 일치.
3. **비용·수익** — Gemini 2.5 Flash-Lite/GPT-5-nano로 1회 분석 약 0.3~0.5원(캐싱 시 월 약 1만원). 수익은 프리미엄(AI 심층분석 유료화) + B2B 교육 라이선스 투 트랙.

## 1. 스파이더 차트 5축 근거

**논지:** "임의로 정한 게 아니라, 자동 코드평가 연구 + 컴퓨팅 사고력(CT) 프레임워크 + 기존 플랫폼의 평가 축을 참고해 초보 학습자 진단 목적에 맞게 5축으로 재구성했다."

> 참고: 각 축의 **세부 항목 표현**(예: 구문→문법·괄호·들여쓰기)은 팀 제안 안이며, 그것이 아래 논문·플랫폼의 평가 방식과 부합하는지 대조·검증한 상태다. 즉 "기준 자체는 연구·플랫폼에서 확인, 세부 항목은 팀 안 + 논문 대조로 다듬음".

### 축별 근거 매핑

| 우리 축 | 핵심 근거 논문 | 플랫폼 참고 | 한 줄 근거 (교수님용) |
|---|---|---|---|
| **구문 정확도** | Ala-Mutka (2005); Keuning et al. (2018) | Codewars(언어별 랭크) | 자동평가 연구가 문법·스타일 오류의 정적 분석을 독립된 표준 평가차원으로 규정 — 우리 "오류 없는 제출 비율"이 직접 구현 |
| **로직 구현도** | Douce et al. (2005); Ala-Mutka (2005) | LeetCode, solved.ac | 테스트케이스 통과율은 "프로그램이 요구대로 동작하는가"를 검증하는 학문적 표준 방법 |
| **개념 이해도** | Brennan & Resnick (2012); Stegeman et al. (2016) | HackerRank(도메인별 인증) | CT 프레임워크가 "computational concepts(반복·조건·자료)"를 핵심 측정차원으로 정의, 검증된 루브릭이 개념의 관용적 사용을 평가 |
| **코드 효율성** | Ala-Mutka (2005); Keuning et al. (2018) | **CodeSignal(정확도 vs 속도 분리)** | 동적 평가 연구가 효율성/성능을 정확성과 별개 평가차원으로 명시 |
| **문제 해석력** | Wing (2006); Grover & Pea (2013) | — | CT 연구가 문제 분해·재정식화(코딩 전 문제 파악)를 구문 정확성과 구별되는 근본 역량으로 취급 |

### 인용 논문 전체 (저자·연도·제목·URL)

**Programming Learning Analytics**
- Ihantola et al. (2015). *Educational Data Mining and Learning Analytics in Programming: Literature Review and Case Studies.* ITiCSE-WGR '15. — https://doi.org/10.1145/2858796.2858798 → 제출/시도 데이터로 실력 측정이 확립된 관행임을 뒷받침 (우리 `ExerciseAttempt` 로그 정당화)
- Hundhausen, Olivares & Carter (2017). *IDE-Based Learning Analytics for Computing Education.* ACM TOCE 17(3). — https://doi.org/10.1145/3105759

**Automated Code Assessment (자동 코드 평가)**
- Ala-Mutka (2005). *A Survey of Automated Assessment Approaches for Programming Assignments.* Computer Science Education 15(2). — https://doi.org/10.1080/08993400500150747 → **가장 중요.** 동적분석(기능·효율·테스트) vs 정적분석(스타일·오류)로 다차원 평가 규정. 5축 중 3축(구문·로직·효율)을 이 한 편이 커버.
- Douce, Livingstone & Orwell (2005). *Automatic Test-Based Assessment of Programming: A Review.* ACM JERIC 5(3). — https://doi.org/10.1145/1163405.1163409
- Keuning, Jeuring & Heeren (2018). *A Systematic Literature Review of Automated Feedback Generation for Programming Exercises.* ACM TOCE 19(1). — https://doi.org/10.1145/3231711 (※ author-hosted PDF는 SSL 오류 → ACM DOI로 인용)

**Programming Skill Assessment (루브릭)**
- Stegeman, Barendsen & Smetsers (2016). *Designing a Rubric for Feedback on Code Quality in Programming Courses.* Koli Calling '16. — https://doi.org/10.1145/2999541.2999555 (백업 PDF: https://www.stgm.nl/quality/stegeman-quality-2016.pdf) → **"우리 축이 검증된 루브릭을 반영한다"의 최고 인용.**
- Lister et al. (2006). *Not Seeing the Forest for the Trees: Novice Programmers and the SOLO Taxonomy.* ITiCSE '06. — https://doi.org/10.1145/1140123.1140157 → 이해도가 이분법 아닌 단계적 측정 구인임을 근거

**Computational Thinking (컴퓨팅 사고력)**
- Wing (2006). *Computational Thinking.* CACM 49(3). — https://doi.org/10.1145/1118178.1118215 (오픈 PDF: https://www.cs.cmu.edu/~15110-s13/Wing06-ct.pdf) → 문제 분해·추상화의 앵커 인용
- Brennan & Resnick (2012). *New Frameworks for Studying and Assessing the Development of Computational Thinking.* AERA 2012. — https://scratched.gse.harvard.edu/ct/files/AERA2012.pdf → 개념/실천/관점 3차원, 가장 많이 인용되는 CT 평가 프레임
- Grover & Pea (2013). *Computational Thinking in K–12: A Review of the State of the Field.* Educational Researcher 42(1). — https://doi.org/10.3102/0013189X12463051
- CSTA & ISTE (2011). *Operational Definition of Computational Thinking.* — https://iste.org/standards/computational-thinking-competencies

> **발표용 최소 인용 스파인:** Ala-Mutka 2005 + Keuning 2018(평가 차원) · Stegeman 2016(초보 루브릭) · Wing 2006 + Brennan-Resnick 2012(CT 역량) · Ihantola 2015(데이터 기반 실력 측정).

## 2. 진단 결과의 신뢰성 (루브릭 기반 평가)

**논지:** "AI가 임의 평가하는 게 아니라, 우리가 먼저 평가기준(Rubric)을 정의하고 AI는 그 기준대로 분석 + 감점 근거를 함께 반환한다. 이것이 2026년 다수 연구의 권고와 일치한다."

### 항목별 세부 평가기준 (발표 슬라이드에 표로)

| 축 | 평가기준 |
|---|---|
| 구문 정확도 | 문법 오류, 괄호·들여쓰기 오류, 예약어 사용 |
| 로직 구현도 | 테스트케이스 통과 여부, 알고리즘 구성, 제어문 활용 |
| 개념 이해도 | 문제가 요구하는 함수·클래스·반복문 등 핵심 개념의 적절한 활용 |
| 코드 효율성 | 중복 코드, 코드 구조, 불필요한 변수 사용 |
| 문제 해석력 | 요구사항 충족, 예외 처리, 입출력 조건 반영 |

### 신뢰성 뒷받침 연구 (LLM-as-a-judge / 루브릭 채점, 2026)

| 논문 | 시사점 | URL |
|---|---|---|
| From Rubrics to Reliable Scores: Evidence-Grounded Text Evaluation with LLM Judges | 고정 기준 + 추적 가능한 근거 + 보정된 점수 해석이 있어야 신뢰 → 우리 "항목별 감점 근거 표시" 정당화 | https://arxiv.org/abs/2601.08654 |
| Reliability without Validity: Large-Scale Evaluation of LLM-as-a-Judge | 재검사 신뢰도는 높으나 위치 편향 존재 → 편향 통제 필요 | https://arxiv.org/abs/2606.19544 |
| Learning to Judge: LLMs Designing and Applying Evaluation Rubrics | 사실·지식 집약 과제는 채점 신뢰도 저하 → **결정적 축(구문·로직)은 룰기반, 개념·해석은 LLM** 분리설계와 부합 | https://arxiv.org/html/2602.08672v1 |
| RubricEval: Rubric-Level Meta-Evaluation Benchmark | 루브릭을 검증가능·객관 항목으로 써야 함 | https://arxiv.org/html/2603.25133v1 |

**발표 한 줄:** "LLM-as-a-judge는 루브릭을 명시하고 항목별 근거를 강제할 때 일관성·신뢰가 오른다는 것이 2026년 연구의 공통 결론이며, CodeMong의 5축 루브릭 + 감점 근거 반환 설계가 이 권고를 따른다."

### 스파이더 차트 생성 흐름
평가 항목 확정 → 단원마다 코드 작성 문제 풀이 → **단원별 스파이더 차트 생성** → 마지막에 학습한 단원만 반영한 **종합 스파이더 차트** 제공. (현재 코드의 `lib/learning/skill-radar.ts` `getSkillRadar`가 이미 이 구조의 씨앗 — 결정적 2축 실측 + AI 3축 데모)

## 3. AI 모델 및 비용

**논지:** "성능뿐 아니라 비용을 함께 고려. 저가 모델 + 프롬프트/캐싱 최적화 + 호출 시점 최소화로 운영비를 하루 300원권으로 방어 가능."
(원화 환산: 1 USD ≈ 1,380원 가정 — 발표 당일 환율로 갱신)

### 저가 모델 가격 비교 (1M 토큰당)

| 모델 | Input | Output | 캐시 input | 출처 |
|---|---|---|---|---|
| **Gemini 2.5 Flash-Lite** | $0.10 | $0.40 | $0.01 | https://ai.google.dev/gemini-api/docs/pricing |
| **GPT-5-nano** | $0.05 | $0.40 | $0.005 | https://developers.openai.com/api/docs/models/gpt-5-nano |
| GPT-4.1-nano | $0.10 | $0.40 | $0.025 | https://developers.openai.com/api/docs/pricing |
| Gemini 2.5 Flash | $0.30 | $2.50 | $0.03 | (동일 pricing 페이지) |
| Claude Haiku 4.5 (비교용) | $1.00 | $5.00 | ~0.1× | Anthropic 카탈로그 |

→ **최저가 티어 = Gemini 2.5 Flash-Lite 또는 GPT-5-nano.** 루브릭 채점엔 이 티어로 충분. Claude Haiku는 품질 높지만 input 기준 10~20배 비쌈.

### 비용 절감 기법

| 기법 | 절감폭 | 출처 |
|---|---|---|
| Gemini context caching (루브릭 캐싱) | 캐시 토큰 **90% 할인** | https://ai.google.dev/gemini-api/docs/caching |
| OpenAI/Anthropic prompt caching | 캐시 input **75~90% 할인** | https://www.prompthub.us/blog/prompt-caching-with-openai-anthropic-and-google-models |
| **제출 시에만 LLM 호출** | 호출 수 자체 최소화 | 아키텍처 원칙 |
| 프롬프트 최적화(짧은 루브릭) | input 비용 선형 절감 | 토큰=비용 |
| Batch API (비실시간, ~24h) | **50% 할인** | OpenAI/Gemini 공통 |
| 유저당 무료 분석 횟수 제한 | 남용 비용 상한 = 프리미엄 전환 트리거 | 운영 정책 |

### 비용 추정 (Flash-Lite, 1회 = input 1,500 + output 500 토큰)

- **캐싱 없음:** 1회 ≈ 0.48원 → 1,000회/일 ≈ **483원/일**, 월 ≈ 14,500원
  - Input: 1,500/1M × $0.10 = $0.00015 / Output: 500/1M × $0.40 = $0.00020 / 합계 $0.00035
- **루브릭 캐싱 적용:** 1회 ≈ 0.33원 → 1,000회/일 ≈ **334원/일**, 월 ≈ **약 1만원**
  - 캐시 input 1,200×$0.01/1M + 신규 300×$0.10/1M + output 500×$0.40/1M ≈ $0.000242

> **"하루 300원 / 월 9,000원" 주장 = 타당(조건부).** ① 하루 1,000건 미만이거나 ② 루브릭 캐싱을 쓰거나 ③ output이 500토큰보다 짧으면 방어 가능. 발표 시 "프롬프트 캐싱 적용 기준, 환율 1,380원" 명시하면 안전.

**핵심 레버:** 루브릭(5축 기준)은 매 호출 반복되는 고정 접두부 → **context caching**에 올리면 input 대부분이 90% 할인.

### 프리미엄/구독 (검증된 사례)

| 플랫폼 | 무료 | 유료 | 유료 내용 | 출처 |
|---|---|---|---|---|
| Codecademy | Basic $0 | Plus/Pro ~$20~40/월 | 실무 프로젝트·수료증·커리어패스 | https://www.codecademy.com/pricing |
| SoloLearn | 무료 코스 | Pro ~$13/월 | 광고 제거·무제한 연습·코드 코치 | https://www.sololearn.com/en/pricing |
| LeetCode | 무료 문제 | Premium $35/월 | 회사별 문제·해설·모의 | https://leetcode.com/subscribe/ |

→ **CodeMong 적용:** 무료 = 이수율·기본 통과 판정 + 결정적 채점(구문·로직), **프리미엄 = AI 3축(개념·효율·해석) 심층 피드백 + 맞춤 추천 + 성장 리포트 + 무제한 AI 분석.** 무료 분석 횟수 제한이 그대로 전환 트리거.

### B2B / 교육 라이선스 (검증된 사례)

| 사례 | 방식/가격 | 출처 |
|---|---|---|
| Codecademy for Business | 좌석당 월 $25(연결제), 강사용 실시간 리포트·진도 대시보드 | https://www.codecademy.com/business |
| 프로그래머스 캠퍼스(그렙) | 기업 교육 토탈 솔루션 + AI 역량평가(응시자당 16,500원~), 맞춤 견적 | https://campus.programmers.co.kr/ |
| LeetCode for Schools | 학교 이메일 인증·기관 단위 학생 할인 | https://leetcode.com/student/ |

→ **CodeMong 적용:** `getSkillRadar`(5축) + 이수율 집계가 이미 **강사용 학습 대시보드의 원재료**를 가짐 → 학교/교육기관에 학생 학습현황+분석 리포트를 제공하는 B2B로 확장 좋음.

## 5. 발표 전체 스토리라인

> 기존 연구·플랫폼 참고해 평가기준 설계 → AI가 미리 정의한 기준으로 코드 분석 → **분석 근거와 함께** 스파이더 차트 제공 → 부족한 영역 진단 → 맞춤 학습·문제 추천

+ **참고 플랫폼·논문 정리 슬라이드 1장 추가** — 교수님이 "왜 이 기준?", "근거가 뭐냐?" 물으면 즉시 근거 제시.
